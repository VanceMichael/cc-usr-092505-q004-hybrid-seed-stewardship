# 杂交稻制种受托与质量追溯

管理杂交稻制种合同、地块隔离、批次质量和匿名价格指数。联盟汇集多家
企业与多个制种县后，同一品种可能由不同受托人在相邻区域繁育；本服务
保证隔离条件、亲本批次、抽检结论与谱系不被混淆，使价格指数与最终
种子质量始终有依据。

## 领域资料

`contracts/domain.schema.json` 记录共享资料结构，`fixtures/domain.json`
是不含真实个人信息的示例。参与方包括种业企业、制种受托人、县级管理
人员、种子检验人员和联盟秘书处。

## 服务模型

`src/hybrid_seed_stewardship/` 为纯标准库实现，无需外部服务：

- `models.py`：不可变值对象（品种权利、技术规程、合同版本、地块绑定、
  谱系节点、检验结论、放行记录、报价与指数、扫码视图）
- `service.py`：`StewardshipService`，在内存台账上强制全部业务不变量
- `errors.py`：业务规则冲突类型

### 关键规则

1. **合同版本链**：企业提交品种权利、亲本来源、目标数量与技术规程形成
   v1；县级绑定地块、受托人等级、隔离区、播插窗口与田间检查派生新版本，
   被台账引用的旧版本永不改写。
2. **资格、隔离与花期**：绑定按品种规程校验受托人等级、隔离距离与播插
   窗口；跨合同的相邻异品种地块花期重叠且距离不足即冲突。
3. **重量守恒**：收获、混样、拆批、合批、加工均核对
   `输入重量 = 输出重量 + 登记损耗`；批次余量被事件原子占用，并行加工
   与抽样不得重复占用同一数量。
4. **谱系追溯**：每袋成品沿台账可回溯到全部来源地块与父母本批次，
   `scan_bag` 返回地块、亲本、谱系事件链、检验与放行历程。
5. **检验与放行**：复核只作用于未放行批次；已放行结论封存，纠正只能
   发布替代版本（不合格时撤销放行，历史结论全部保留）。放行人与生产
   提交人必须相互独立，放行时复核最新结论、风险挂起与受托人当前资格。
6. **风险边界**：花期冲突、气候风险、资格变化只挂起尚未放行的批次；
   已放行批次列入"不受影响"，不被追溯改动。
7. **可见性**：企业只能看本企业合同与本企业报价的门槛判定。
8. **匿名指数**：秘书处设门槛（最小数量、最少报价家数、价格区间），
   只有通过门槛的匿名报价按数量加权计入指数；纳入与排除的逐条理由
   可通过 `explain_quote` 追问；通过家数不足时指数不发布。

## 开发命令

- 运行测试：`python3 -m unittest discover -s tests -v`
- 编译或构建：`python3 -m compileall -q src/hybrid_seed_stewardship tests`

上述命令只读取仓库内文件，不连接外部业务服务。
